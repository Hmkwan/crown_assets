# 企业级审批流角色与流程配置指南

## 常用企业角色定义

| 角色代码 | 中文名称 | 职责说明 | 典型权限 |
|---------|---------|---------|---------|
| `employee` | 申请人 | 普通员工，发起各类申请 | 创建申请、查看自己的申请 |
| `department_head` | 部门经理 | 部门负责人，第一级审批 | 审批本部门申请 |
| `admin` | IT资产管理员 | IT设备管理、分配、维护 | 管理设备、审核技术规格 |
| `procurement` | 采购 | 采购评估、询价、下单 | 评估报价、创建采购单 |
| `warehouse` | 库房 | 库存管理、出入库 | 管理库存、物流记录 |
| `security` | 安全/合规 | 信息安全、合规审查 | 敏感权限审批、数据安全检查 |
| `finance` | 财务 | 预算、核销、资产账务 | 预算确认、资产核销 |
| `executive` | 总经理/高层 | 高额或战略性决策 | 最终审批、例外处理 |
| `auditor` | 审计/稽核 | 流程监督、合规审查 | 只读审计、流程监控 |

## 典型流程配置

### 1. 设备申请（新购/补件）- 8节点企业级

```
[申请提交] 
  ↓
[直属主管审批] (department_head, 2天超时)
  ↓
[IT资产管理员审核] (admin, 3天超时) - 检查型号/规格/标准化
  ↓
[采购评估与报价] (procurement, 5天超时, 并行可选)
  ↓
[条件判断: 金额>5万?]
  ├─ 是 → [财务预算确认] (finance, 3天)
  └─ 否 → 跳过
  ↓
[条件判断: 金额>10万 或 特殊类别?]
  ├─ 是 → [高层审批] (executive, 7天, 可升级)
  └─ 否 → 跳过
  ↓
[采购下单与入库] (auto动作: 生成PO, 通知仓库, 更新库存)
  ↓
[IT分配设备] (admin, 动作: 分配给用户, 记录资产)
  ↓
[完成]
```

**配置要点**:
- 条件分支按金额/设备类型（如服务器需额外安全审批）
- 并行节点支持采购与财务同步评估
- 自动动作触发采购单生成、库存更新

---

### 2. 权限申请（账号/系统权限）- 4节点

```
[申请提交] - 说明用途/期限
  ↓
[直属主管审批] (department_head, 2天) - 业务合理性
  ↓
[系统管理员审批] (admin, 3天) - 最小权限校验
  ↓
[安全合规审批] (security, 2天) - 敏感权限审查
  ↓
[自动生效] (auto动作: 创建账号, 赋权, 设置到期回收)
  ↓
[完成]
```

**配置要点**:
- 支持临时权限与自动到期回收
- 敏感系统需经过security审批
- 自动动作在最后节点触发账号创建与权限分配

---

### 3. 设备借用（短期）- 5节点

```
[借用申请] - 借用时间/用途
  ↓
[主管确认] (department_head)
  ↓
[库房确认] (warehouse) - 检查库存/设备状态
  ↓
[IT记录出库] (admin, 动作: 登记借用记录, 状态改为loaned)
  ↓
[定时提醒] (到期提醒 → 归还记录 → 检验)
  ↓
[完成]
```

**配置要点**:
- 支持续借申请（重新发起流程）
- 逾期自动通知/升级（后台调度器）
- 归还时需检验设备状态

---

### 4. 设备调拨（部门间）- 4节点

```
[调拨申请] - 来源部门/目标部门/设备ID
  ↓
[来源部门主管审批] (department_head)
  ↓
[目标部门主管确认] (department_head) - 接收意愿
  ↓
[IT/库房执行调拨] (admin + warehouse, 动作: 更新部门, 物流记录, 序列号变更)
  ↓
[完成]
```

**配置要点**:
- 需两个部门主管都同意
- 自动更新资产归属部门
- 记录物流轨迹

---

### 5. 配件申请（充电器/网线等）- 简化3节点

```
[配件申请]
  ↓
[主管审批] (department_head, 可选批量处理)
  ↓
[IT确认发放] (admin, 动作: 扣减库存, 记录领用)
  ↓
[完成]
```

**配置要点**:
- 简化流程（小额/高频）
- 支持批量审批（一次多个申请）
- 自动扣减库存

---

### 6. 设备报废 - 6节点企业级

```
[报废申请] - 设备ID, 原因, 照片/检验结果
  ↓
[IT检查确认] (admin) - 确认故障/不可修
  ↓
[安全/合规确认] (security) - 数据销毁/证书作废
  ↓
[财务核销] (finance) - 资产账面价值处理
  ↓
[条件判断: 价值>1万?]
  ├─ 是 → [高层批准] (executive)
  └─ 否 → 跳过
  ↓
[执行报废] (auto动作: 状态改retired, 生成报废单, 财务核销, 存档)
  ↓
[完成]
```

**配置要点**:
- 安全确认必须验证数据已擦除
- 高价值资产需高层审批
- 自动生成报废单并归档

## 高级特性配置

### 并行审批示例
```json
{
  "node_type": "approval",
  "is_parallel": true,
  "approver_user_ids": [101, 102, 103],
  "required_approvals": 2,  // 3人中至少2人同意
  "timeout_seconds": 432000  // 5天
}
```

### 条件分支示例
```json
{
  "node_type": "condition",
  "condition_expr": "amount > 50000 OR category == 'server'",
  "metadata": {
    "true_next_node": "finance_approval",
    "false_next_node": "skip_to_final"
  }
}
```

### 自动动作示例
```json
{
  "actions_on_approve": [
    {"name": "create_po", "action": "generate_purchase_order"},
    {"name": "notify_warehouse", "action": "send_email"},
    {"name": "update_inventory", "action": "add_stock", "params": {"quantity": 1}}
  ],
  "actions_on_reject": [
    {"name": "notify_requester", "action": "send_rejection_email"}
  ]
}
```

### 超时与升级
```json
{
  "timeout_seconds": 172800,  // 2天
  "escalation_target": "executive",  // 超时升级给高层
  "escalation_action": "auto_approve_or_reassign"
}
```

## 实施建议

1. **分阶段上线**: 先实施维修、配件等简单流程，再上复杂的设备采购流程
2. **灰度切换**: 使用Feature Flag，允许部分部门先试用新流程
3. **数据迁移**: 将现有approval_workflow数据映射到新引擎
4. **培训**: 为管理员提供流程设计器培训，为用户提供审批操作指南
5. **监控**: 设置SLA告警，监控超时审批与失败动作
